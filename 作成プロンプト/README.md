# Recipe Refinerの作成経緯

Recipe Refinerは、ChatGPTとの対話でアプリの要件を整理し、その対話から作成した実装プロンプトをCodexに渡して開発したWebアプリです。

この「作成プロンプト」フォルダには、アイデアの相談から、質問への回答、実装プロンプトの作成、追加要件を反映した改訂までの記録を保存しています。ChatGPTで実装のための指示を作り、Codexでアプリを実装する、という流れをたどれます。

元のやり取りは[ChatGPTの共有チャット](https://chatgpt.com/share/6abe5ce0-63fc-83e8-87b1-f7905928c23e)でも確認できます。アプリの環境構築・起動方法・使い方は[プロジェクトのREADME](../README.md)を参照してください。

## 作りたかったアプリ

ネットや書籍のレシピを左側に入力し、右側に「材料がない」「別の材料に置き換えたい」「人数を変えたい」などの変更希望を入力すると、その条件に合わせてレシピをリファインするアプリを考えました。

材料の変更に伴う分量、水分量、味付け、加熱時間、調理工程への影響を考慮し、変更の必要がない部分は元レシピを維持することを重視しています。

## アプリができるまで

### 1. ChatGPTにアイデアを伝える

最初に、アプリの目的と左右に分けた入力画面のイメージを説明しました。自分が分かる言語はPythonとJavaScriptであることも伝え、その範囲で扱える構成を前提にしました。

この段階でChatGPTには、実装プロンプトを作るために必要な情報を質問し、十分な情報が集まったらCodex用のプロンプトにまとめるよう依頼しました。

### 2. 質問に答えて要件を決める

ChatGPTから、Webフレームワーク、LLM、レシピの入力方法、結果の表示形式、保存、履歴、UI、テストなどについて30項目の質問がありました。それぞれに回答し、次のような方針を決めました。

| 項目 | 決めた内容 |
| --- | --- |
| バックエンド | Django |
| フロントエンド | HTML・CSS・Vanilla JavaScript |
| LLM | OpenAI APIとOpenAI互換APIのローカルLLMに対応 |
| 入力 | 元レシピと変更希望を手入力・コピー＆ペーストで入力 |
| 出力 | 料理名、材料、分量、手順、補足を構造化して表示。変更点も表示 |
| レシピの変更方針 | 元レシピをなるべく維持し、変更に伴う調整も行う |
| 大きな変更 | 料理として成立しにくい場合などはユーザーに再確認 |
| 保存 | SQLiteに保存し、履歴とお気に入りを用意 |
| 継続的な修正 | 生成結果に追加指示を出して再リファイン |
| 利用形態 | ログイン不要の個人用・PC向けローカルアプリ |
| 開発・検証 | Pythonの依存管理にuvを使用。Dockerは使わず、テストとREADMEを作成 |
| 将来対応 | 冷蔵庫の材料管理や本格的なアレルギー管理など |

質問への回答では開発環境の候補にnpmも含まれていましたが、実装プロンプトではDjango TemplatesとVanilla JavaScriptを使い、Node.js/npmによるフロントエンドのビルド工程を不要にする構成に整理されました。

### 3. 初回のCodex用プロンプトを作る

回答をもとに、ChatGPTが実装用のプロンプトを作成しました。画面や機能に加え、データモデル、LLMの呼び出し構造、出力の検証、エラー処理、テスト、README、実装後の確認までをまとめた内容です。

アプリ名は未定だったため、プロンプトでは仮の表示名として「Recipe Refiner」が提案されました。

### 4. LLM設定について追加要件を伝える

初回のプロンプトを受けて、OpenAI APIとローカルLLMの切り替えをYAMLファイルで設定できるようにする要件を追加しました。

ChatGPTはこの要件を反映して、プロンプト全体を再出力しました。初回の画面上でのProvider切り替え案を変更し、次の設定方針を明確にしました。

- Provider、モデル名、接続先URL、API方式、タイムアウトなどは `settings/llm.yaml` にまとめる。
- APIキーなどの秘密情報は `.env` に分ける。
- 画面には現在のProviderとモデルを表示し、設定の変更はYAMLで行う。
- 生成履歴には、そのとき使用したProvider・モデル・API方式を残す。

### 5. 作成したプロンプトをCodexに渡して実装する

ChatGPTとのやり取りで作成したプロンプトをCodexに渡し、Recipe Refinerを実装しました。ChatGPTとの対話で整理した要件が、Codexへの具体的な実装指示になっています。

改訂版では、実装後に環境構築、マイグレーション、Djangoのチェック、テストを行うことも指示しています。また、通常のテストでは外部LLMへ接続せず、モックを使用することを指定しています。

このフォルダはChatGPTでプロンプトを作成した過程の記録です。Codexでの実装中の会話やテスト実行ログは、このフォルダの記録には含まれていません。

## この作り方のポイント

最初にアプリの目的と自分が扱える技術を伝え、質問に答えながら機能と範囲を具体化しました。その後、設定方法の追加要件を反映してプロンプトを改訂し、Codexへ実装を依頼しました。

アイデア、要件の決定、実装指示を順に記録しておくことで、なぜこの技術構成や機能を選んだのかを後から確認できます。
